# Приёмка и репетиция защиты

Перед защитой на чистом компьютере выполните:

```bash
docker compose up --build -d
docker compose ps
python3 scripts/acceptance.py
```

`career-quest` должен получить статус `healthy`. Скрипт приёмки работает с
временной SQLite-базой и проверяет импорт, пять демо-аккаунтов, изоляцию профиля
сотрудника, рекомендации, однократное завершение активности и HR-обзор. Он также
измеряет локальный расчёт employee/HR dashboard; целевой предел для каждого —
менее 2 секунд.

## Репетиция на защите

1. Покажите команду запуска и `docker compose ps`.
2. Войдите как Middle и откройте объяснение рекомендации: критический разрыв,
   ожидаемый прирост и история участия должны быть видны на одной карточке.
3. Войдите как Junior, начните `System Design Fundamentals`, завершите его в
   демо и покажите новые уровни API Design/System Design и обновлённое покрытие.
4. Войдите как HR, отфильтруйте срез и откройте профиль сотрудника. Объясните,
   что сигналы — это приглашение к поддержке, а не оценка эффективности.
5. Загрузите проверочный `employees.json` и `activity_history.csv`, затем
   откройте его траекторию и рекомендации.

## Что проверить отдельно

- Все пять демо-учётных записей работают сразу после первого старта.
- Сотрудник не может открыть HR API или чужой `employee_id`; HR видит только
  внутренний HR-контур.
- Неверный пакет импорта не частично изменяет базу.
- `make demo-reset` требует `reset-demo` и возвращает исходный набор.
- При заданных `LLM_API_URL`, `LLM_API_KEY` и `LLM_MODEL` проверьте один ответ
  реального провайдера. Без этих переменных приложение честно показывает
  `rules_fallback`; этот режим входит в автоматическую приёмку.

На текущей машине Docker не установлен, поэтому `docker compose up` здесь не
запускался. Локально проверены bootstrap, HTTP-сценарии и автоматические тесты.
