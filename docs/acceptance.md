# Приёмка и репетиция защиты

## Проверки без внешнего AI

На чистом компьютере нужен Docker с Compose:

```bash
docker compose up --build -d
docker compose ps
docker compose exec -T career-quest python -m unittest discover -s backend/tests -v
docker compose exec -T career-quest python scripts/acceptance.py
docker compose exec -T career-quest python scripts/evaluate_recommendations.py
```

Сервис должен получить статус `healthy`: `/api/health` проверяет наличие данных,
пользователей и версии данных в SQLite, а не только отдачу HTML.

Без Docker, из корня репозитория с Python 3.10+:

```bash
python3 -m unittest discover -s backend/tests -v
python3 scripts/acceptance.py
python3 scripts/evaluate_recommendations.py
```

Тесты используют `data/career_quest_dataset`, а не персональную папку Downloads.
Отсутствие датасета приводит к ошибке, а не тихому пропуску проверок.

Скрипт приёмки создаёт временную базу, запускает HTTP-сервер на свободном
loopback-порту и проверяет пять входов, права, смену цели, однократное завершение,
персональный сброс, предварительную проверку/импорт трёх профилей, повторный импорт,
отклонение неверного пакета, рекомендации для загруженных профилей, HR-аналитику,
повторную инициализацию с сохранением данных и выход. Внешний AI принудительно
отключён. Измеряется время HTTP-запросов; это не замер браузерного рендера или
производительности реального провайдера.

## Оценка рекомендаций

В `examples/jury/` находятся три дополнительных синтетических профиля в исходной
схеме. Они не загружаются при обычном старте. Это авторские проверки, а не скрытые
профили организаторов:

1. Критический System Design важнее минимального Public Speaking с тремя пропусками.
2. После пропусков очного архитектурного обучения доступна онлайн-альтернатива.
3. Продвинутые мероприятия заблокированы prerequisites, менторская активность уже завершена.

`expectations.json` задаёт допустимый первый шаг и запрещённые события, отдельно
от кода рекомендаций. Скрипт сравнивает многофакторные правила с выбором минимального
навыка и проверяет допустимость, фактические объяснения и задержку.

Для сравнения с **реальным AI**, после настройки `.env` и пересоздания сервиса:

```bash
docker compose exec -T career-quest python scripts/evaluate_recommendations.py --with-ai
```

Команда делает три запроса к настроенному провайдеру; возможна оплата API.
Она завершится ошибкой при fallback вместо AI, задержке от 10 секунд или
невыполнении критериев. Поддельный ответ селектора в unit-тесте подтверждает
контракт интеграции, но не качество настоящей модели.

## Репетиция в браузере

1. Откройте `http://127.0.0.1:8000`, войдите как Junior. Профиль появляется
   независимо от ответа AI; ожидание видно только в блоке рекомендаций.
2. Покажите все требования цели, критические дефициты и прогноз по шагам.
3. Начните `System Design Fundamentals`, завершите в диалоге и покажите
   фактические изменения. Повторное завершение не должно добавлять навык.
4. Смените карьерную цель и убедитесь, что рекомендации пересчитались. Кнопка
   «Сбросить демо» возвращает исходную цель и удаляет только созданные этим
   сотрудником через приложение активности.
5. Войдите как HR. Проверьте фильтры, доли критических дефицитов по подразделениям,
   помесячное добровольное участие и исходную историю в карточке сотрудника.
6. Выберите `examples/jury/employees.json` и `activity_history.csv`. Нажмите
   «Проверить пакет», затем «Подтвердить импорт». Откройте профиль из отчёта.
   В полном режиме здесь должен появиться AI с объяснениями, как у сотрудника.
7. Повторите импорт: новых записей должно быть 0. Попробуйте неизвестную целевую
   роль: получите ошибку с идентификатором профиля, HR-обзор продолжит работать.
8. Остановите и снова поднимите сервис: импорт и прогресс сохраняются.

`make demo-reset` или `sh scripts/demo-reset.sh` — отдельный полный сброс тома.
Он требует запущенный сервис с `DEMO_MODE=true` и ввод `reset-demo`; удаляет также
профили жюри. Это отличается от персонального сброса в кабинете.

## Зафиксированные границы проверки

Локально проверены Python-тесты, HTTP-приёмка и три синтетических сценария.
Результат правил на этих сценариях — 3/3 допустимых первых шагов; простого выбора
минимального навыка — 1/3. Этот небольшой набор не доказывает обобщающую способность.
Docker в текущем окружении отсутствует. Сборку образа, запуск на чистом компьютере
и ответы реального провайдера нужно проверить приведёнными командами; они не
подменяются результатами локальных тестов.
