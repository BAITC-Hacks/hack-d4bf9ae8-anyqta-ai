# Career Quest

Career Quest — веб-платформа развития сотрудников для кейса Halyk Bank на
HackAlem AI. Сотрудник видит карьерную цель, актуальные навыки и объяснимые
следующие шаги. HR получает агрегированный срез дефицитов компетенций и может
загрузить проверочные профили жюри.

## Быстрый запуск для жюри

Нужен Docker Desktop или Docker Engine с Docker Compose. В комплект уже входит
синтетический стартовый набор: никаких путей к `Downloads`, Python, Node.js или
PostgreSQL на компьютере жюри не требуется.

```bash
docker compose up --build -d
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Первый запуск собирает
образ, применяет миграции, импортирует 200 профилей, 40 мероприятий и 2 743
записи истории, затем создаёт демо-аккаунты. Готовность проверить командой:

```bash
docker compose ps
```

У сервиса `career-quest` должен быть статус `healthy`. Если порт 8000 занят,
создайте `.env` из `.env.example`, измените `CAREER_QUEST_PORT` и откройте
соответствующий порт.

| Логин | Пароль | Роль и сценарий |
|---|---|---|
| `junior@careerquest.demo` | `DemoEmployee2026!` | Junior: путь к Middle |
| `middle@careerquest.demo` | `DemoEmployee2026!` | Middle: критический разрыв и история участия |
| `senior@careerquest.demo` | `DemoEmployee2026!` | Senior: путь к Lead |
| `lead@careerquest.demo` | `DemoEmployee2026!` | Lead: межролевую цель |
| `hr@careerquest.demo` | `DemoHR2026!` | HR: компетенции, сигналы поддержки и импорт |

## Сценарий проверки

1. Войдите как `middle@careerquest.demo` и откройте объяснение следующего шага:
   система использует требования Senior, критические навыки и историю участия.
   Профиль загружается сразу, рекомендации — отдельно. Раскройте все требования
   и посмотрите прогноз покрытия после последовательного выполнения шагов.
2. Войдите как `junior@careerquest.demo`, начните `System Design Fundamentals`,
   затем нажмите «Завершить в демо». Покрытие требований и рекомендации
   пересчитаются, повторное завершение не добавит навык второй раз. Кнопка
   «Сбросить демо» вернёт только этого сотрудника к исходному состоянию.
   Можно выбрать другую карьерную цель; сброс также отменяет этот выбор.
3. Войдите как HR, примените фильтр, откройте сотрудника и загрузите
   `employees.json` вместе с `activity_history.csv` в исходной схеме. Ошибка
   в пакете не изменит данные. Сначала нажмите «Проверить пакет», затем
   «Подтвердить импорт». В отчёте есть ссылки на профили и счётчики добавленных
   и уже существующих записей. Для репетиции используйте файлы из `examples/jury/`.
4. В HR проверьте доли критических дефицитов по отделам, динамику добровольного
   участия за 12 месяцев и исходную историю в карточке сотрудника.

## AI-режим рекомендаций

Без настроек модели приложение работает в `rules_fallback`: оно подбирает
активности по проверяемым правилам и показывает это в кабинете. В AI-режиме
модель выбирает до трёх шагов из списка, который уже отфильтровал сервер.

Сервер передаёт модели контекст развития без имени и логина: роль, грейд, стаж,
формат работы, язык, цель и дефициты. У кандидатов есть описание, формат,
навыки с точным приростом, расписание и до 12 последних записей добровольного
участия за год по пересекающимся навыкам. Пропуски несвязанных тем не штрафуют
активность только из-за одинакового типа мероприятия.
Модель не получает пароль, не меняет уровни навыков и не может предложить
событие вне этого списка. После ответа сервер снова проверяет каждый `event_id`.

### Подключение OpenAI API

В новой копии репозитория скопируйте `.env.example` в `.env`. Если `.env` уже
существует, сохраните свои настройки. Файл исключён из Git. Заполните все три
переменные:

```env
LLM_API_URL=https://api.openai.com/v1/chat/completions
LLM_API_KEY=ваш_секретный_API_ключ
LLM_MODEL=название_модели_из_вашего_OpenAI-проекта
```

`LLM_MODEL` укажите ровно так, как модель называется в вашем OpenAI-проекте.
Приложение использует OpenAI-совместимый Chat Completions endpoint и ожидает
от модели JSON-ответ. Все три переменные обязательны одновременно; если не
указать ни одной, останется `rules_fallback`. Неполная конфигурация также
включает резервный режим с понятным сообщением и не блокирует кабинет.

После изменения `.env` пересоздайте контейнер:

```bash
docker compose up --build -d --force-recreate
```

Войдите под сотрудником или откройте профиль через HR, включая загруженный
профиль жюри. В «Следующих шагах» используются один сервис и кэш. При успешном ответе
будет виден статус **«AI выбрал шаги из проверенного списка»**. При недоступности модели, таймауте или
некорректном JSON приложение не остановится: оно вернётся к правилам и покажет
причину резервного режима.

Не добавляйте `.env` в Git и не передавайте ключ в браузер: он используется
только сервером. OpenAI также рекомендует хранить ключ в серверной переменной
окружения. [Официальная документация OpenAI](https://platform.openai.com/docs/quickstart/make-your-first-api-request)

## Управление и диагностика

```bash
docker compose logs --tail=100 career-quest
docker compose down
make demo-reset
docker compose exec -T career-quest python scripts/acceptance.py
docker compose exec -T career-quest python scripts/evaluate_recommendations.py
```

`docker compose down` сохраняет локальный прогресс в Docker volume. `make
demo-reset` (или `sh scripts/demo-reset.sh`) проверит `DEMO_MODE` в запущенном
сервисе, потребует ввести `reset-demo`, удалит volume этого демо,
включая импортированные профили и прогресс, и поднимет чистое исходное состояние.

Подробности команд разработки находятся в [backend/README.md](backend/README.md).
Полный план и принятые решения — в [analysis.md](analysis.md).
Полный чек-лист финальной приёмки — в [docs/acceptance.md](docs/acceptance.md).

## Как устроен подбор и прогресс

Один Python-сервис отдаёт API и веб-страницу; SQLite хранится в постоянном томе.
Демо использует фиксированную дату **2026-10-01** из стартового набора.

- Сервер проверяет аудиторию, prerequisites, доступность, добровольность и историю
  завершений. AI выбирает реальные ID и выделяет факторы из проверенного списка;
  отображаемые числа и объяснения строятся из серверных фактов.
- Навык после завершения: `max(текущий, min(5, max_level, текущий + gain))`.
  Учитываются записи после последней оценки и не позже даты демо.
- Покрытие: сумма `min(текущий уровень, требование)` / сумма требований × 100%.
  Прогноз шагов рассчитывается последовательно, без двойного учёта прироста.
  Шаги, не сокращающие разрыв после предыдущих, исключаются из набора.
- AI-результат кэшируется до 15 минут, fallback — на 15 секунд. Изменение
  профиля, цели, истории или каталога инвалидирует кэш через версию данных.
  Если данные изменились во время ответа модели, устаревший результат отбрасывается.
- Цель сотрудника хранится отдельно от исходного импортированного профиля.
  Персональный сброс сохраняет исходную историю и чужие данные.

## Проверка качества AI

После настройки модели выполните сравнение на трёх синтетических профилях:

```bash
docker compose exec -T career-quest python scripts/evaluate_recommendations.py --with-ai
```

Будет сделано три обращения к провайдеру (возможна оплата API). Отчёт показывает
выбор минимального навыка, многофакторные правила и реальную модель, допустимость
первых шагов и задержку. Без `--with-ai` тест не обращается во внешнюю сеть.
Критерии и границы проверки описаны в [docs/acceptance.md](docs/acceptance.md).

Локальные проверки прошли; Docker недоступен в окружении разработки, поэтому
запуск контейнера и качество реального AI здесь не подтверждены.
