# Career Quest

Career Quest — веб-платформа развития сотрудников для кейса Halyk Bank на
HackAlem AI. Сотрудник видит карьерную цель, актуальные навыки и объяснимые
следующие шаги. HR получает агрегированный срез дефицитов компетенций и может
загрузить проверочные профили жюри.

## Быстрый запуск для жюри

Нужен Docker Desktop или Docker Engine с Docker Compose. В комплект уже входит
синтетический стартовый набор: никаких путей к `Downloads`, Python, Node.js или
PostgreSQL на компьютере жюри не требуется.

```bash
docker compose up --build -d
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Первый запуск собирает
образ, применяет миграции, импортирует 200 профилей, 40 мероприятий и 2 743
записи истории, затем создаёт демо-аккаунты. Готовность проверить командой:

```bash
docker compose ps
```

У сервиса `career-quest` должен быть статус `healthy`. Если порт 8000 занят,
создайте `.env` из `.env.example`, измените `CAREER_QUEST_PORT` и откройте
соответствующий порт.

| Логин | Пароль | Роль и сценарий |
|---|---|---|
| `junior@careerquest.demo` | `DemoEmployee2026!` | Junior: путь к Middle |
| `middle@careerquest.demo` | `DemoEmployee2026!` | Middle: критический разрыв и история участия |
| `senior@careerquest.demo` | `DemoEmployee2026!` | Senior: путь к Lead |
| `lead@careerquest.demo` | `DemoEmployee2026!` | Lead: межролевую цель |
| `hr@careerquest.demo` | `DemoHR2026!` | HR: компетенции, сигналы поддержки и импорт |

## Сценарий проверки

1. Войдите как `middle@careerquest.demo` и откройте объяснение следующего шага:
   система использует требования Senior, критические навыки и историю участия.
2. Войдите как `junior@careerquest.demo`, начните `System Design Fundamentals`,
   затем нажмите «Завершить в демо». Покрытие требований и рекомендации
   пересчитаются, повторное завершение не добавит навык второй раз. Кнопка
   «Сбросить демо» вернёт только этого сотрудника к исходному состоянию.
3. Войдите как HR, примените фильтр, откройте сотрудника и загрузите
   `employees.json` вместе с `activity_history.csv` в исходной схеме. Ошибка
   в пакете не изменит данные; успешный профиль сразу доступен в обзоре.

## AI-режим рекомендаций

Без настроек модели приложение работает в `rules_fallback`: оно подбирает
активности по проверяемым правилам и показывает это в кабинете. В AI-режиме
модель выбирает до трёх шагов из списка, который уже отфильтровал сервер.

Сервер передаёт модели только контекст развития: карьерную цель, разрывы
навыков, критичность, ожидаемый прирост и агрегированную историю участия.
Модель не получает пароль, не меняет уровни навыков и не может предложить
событие вне этого списка. После ответа сервер снова проверяет каждый `event_id`.

### Подключение OpenAI API

Файл `.env` уже создан локально и исключён из Git. Заполните в нём все три
переменные:

```env
LLM_API_URL=https://api.openai.com/v1/chat/completions
LLM_API_KEY=ваш_секретный_API_ключ
LLM_MODEL=название_модели_из_вашего_OpenAI-проекта
```

`LLM_MODEL` укажите ровно так, как модель называется в вашем OpenAI-проекте.
Приложение использует OpenAI-совместимый Chat Completions endpoint и ожидает
от модели JSON-ответ. Все три переменные обязательны одновременно; если не
указать ни одной, останется безопасный `rules_fallback`.

После изменения `.env` пересоздайте контейнер:

```bash
docker compose up --build -d --force-recreate
```

Войдите под любым сотрудником и откройте «Следующие шаги». При успешном ответе
будет виден статус **«AI-режим включён»**. При недоступности модели, таймауте или
некорректном JSON приложение не остановится: оно вернётся к правилам и покажет
причину резервного режима.

Не добавляйте `.env` в Git и не передавайте ключ в браузер: он используется
только сервером. OpenAI также рекомендует хранить ключ в серверной переменной
окружения. [Официальная документация OpenAI](https://platform.openai.com/docs/quickstart/make-your-first-api-request)

## Управление и диагностика

```bash
docker compose logs --tail=100 career-quest
docker compose down
make demo-reset
make acceptance
```

`docker compose down` сохраняет локальный прогресс в Docker volume. `make
demo-reset` потребует ввести `reset-demo`, удалит только volume этого демо,
включая импортированные профили и прогресс, и поднимет чистое исходное состояние.

Подробности команд разработки находятся в [backend/README.md](backend/README.md).
Полный план и принятые решения — в [analysis.md](analysis.md).
Полный чек-лист финальной приёмки — в [docs/acceptance.md](docs/acceptance.md).
